# Правила проекта

Работать на русском языке, кратко и без повторов.

Перед изменениями изучить `docs/INDEX.md`, связанную фичу и релевантные архитектурные и дизайн-документы.

## Документация

- `docs/architecture` описывает актуальную архитектуру.
- `docs/design` описывает актуальные дизайн-решения.
- `docs/features` содержит отдельный каталог для каждой фичи.
- Каждый каталог внутри `docs` начинается с `INDEX.md`.
- Пока `INDEX.md` не превышает 1000 строк, не создавать рядом дополнительные Markdown-файлы.
- После разделения оставить в `INDEX.md` краткий обзор и ссылки без дублирования.
- Не создавать `decisions`, ADR, журналы решений и `tasks`. Историю хранит Git.

## Изменения

- Не выходить за область текущей задачи.
- Не добавлять зависимости, не менять публичные контракты и схемы данных без согласования.
- Не отключать тесты, анализаторы, линтеры и предупреждения ради успешной проверки.
- Не откатывать и не перезаписывать чужие изменения.
- Писать комментарии только там где это реально необходимо.


## Git

- Не выполнять commit, push и merge без явного разрешения.
- Использовать conventional commit для комментария комита.


## Готовность

- Изменённое поведение проверено.
- Релевантные тесты и проверки проходят.
- Документация фичи, архитектуры и дизайна соответствует текущему состоянию.
- В итоговом ответе перечислены выполненные проверки и оставшиеся риски.
