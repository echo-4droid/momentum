# Обмен секретами

## Статус

MVP реализован (сервер + клиент + сборка). E2E пройден. Остаток: замер времени Argon2id на средних смартфонах; выкладка на VPS.

## Описание

Отправитель на странице клиента пишет текст (≤ 10 000 символов) и при желании прикладывает файл (≤ 5 МБ). Клиент шифрует всё содержимое локально (Argon2id + AES-256-GCM, версионированный конверт). По умолчанию 32-байтный ключ остаётся в URL-фрагменте ссылки; в режиме «фраза отдельно» клиент генерирует фразу из 6–10 слов EFF. На сервер уходит только шифроблоб с TTL (по умолчанию 24 ч, максимум 7 дней). Отправитель передаёт получателю ссылку (и фразу — в режиме фразы) любыми каналами по своему выбору. Получатель открывает ссылку, клиент расшифровывает локально. По умолчанию секрет сгорает после первого чтения.

## Ожидаемый результат

Веб-страница, на которой за один экран можно: создать секрет → получить ссылку и фразу → передать их получателю → получатель прочёл → секрет уничтожен. Без регистрации.

## Поведение

- Создание: форма текста + файл; выбор режима передачи ключа: «ключ в ссылке» (по умолчанию, ключ в URL-фрагменте) и «фраза отдельно» (фразу генерирует клиент; создатель выбирает число слов 6–10 и может перегенерировать фразу; под полем — её энтропия в битах); выбор TTL (24 ч по умолчанию, до 7 дней); переключатель «сжечь после прочтения» (включён по умолчанию); настройки показа у получателя: «скрыть содержимое через» (выкл/15 с/30 с/60 с, по умолчанию 30 с) и «удалить со страницы через» (выкл/5 мин/10 мин/30 мин, по умолчанию 10 мин). Настройки показа зашифровываются в payload (поле `view`) и остаются внутри конверта.
- Чтение: страница `/s/<id>` сразу проверяет доступность (`GET /api/v1/secrets/{id}/status` — флаг доступности, блоб остаётся на сервере); для прочитанного или истёкшего секрета вместо кнопки «Открыть» выводится «Секрет недоступен…» — полезно при повторной передаче ссылки. Далее — предупреждение об одноразовости рядом с кнопкой «Открыть»; блоб запрашивается у сервера по нажатию кнопки. Полученный блоб держится в памяти до конца открытия: неверная фраза — повторная расшифровка по локальной копии. В режиме «ключ в ссылке» поле фразы скрыто; после открытия страницы фрагмент с ключом срезается из URL и истории. Далее расшифровка на клиенте. Содержимое: сообщение с «Копировать», вложение с «Скачать». Подсказка под содержимым отражает включённые таймеры: при скрытии — «Через N с содержимое скроется — „Показать содержимое“ вернёт его», при удалении — «Через N мин содержимое будет убрано с этой страницы и не вернётся в этом открытии», с обоими таймерами — обе строки, с выключенными — «Сохраните нужное перед закрытием страницы». При включённом удалении по истечении таймера содержимое убирается со страницы до конца открытия (дедлайн стабилен), вместо занавеса — карточка об истёкшем времени показа.
- Хранение: сервер видит непозрачный блоб, ID, время жизни и флаг one_time; режим конверта и настройки показа остаются внутри шифротекста. Суммарный размер хранимых блобов ограничен квотой (2 ГиБ по умолчанию + резерв диска 512 МиБ); при превышении — 507 (квота устойчива к параллельным вставкам). Исчерпание квоты одним анонимным клиентом — вектор атак на доступность (DoS); модель безопасности: [idea.md](../../idea.md).
- Выдача секрета и статус — с `Cache-Control: no-store`: шифротекст живёт только в памяти браузера.
- Удаление: первое чтение (one_time) или TTL — что раньше; немедленное логическое удаление записи (блоб получает победитель удаления: одно чтение — одна выдача).

## Область

Веб-клиент (создание и чтение), серверное API `POST/GET /api/v1/secrets` и `GET /api/v1/secrets/{id}/status`, фоновая чистка просроченного, криптомодуль клиента.

## Затрагиваемые части

`client/` — Expo web (криптомодуль `src/crypto.ts`, экраны Create/Read, API). `server/` — ASP.NET Core Minimal API, слои: `Api/` (`VaultEndpoints` — HTTP-обработчики; маршруты в `Program.cs`), `Domain/` (`VaultService` — правила TTL/id/размера), `Infrastructure/` (`VaultStore` — LiteDB, фоновая чистка), `Installers/` (типизированный конфиг `MomentumOptions`/`VaultOptions`/`RateLimiterLimits`, DI, конвейер), `Constants/`, точка сборки `Program.cs`, тесты. Стык клиент→сервер: `client/dist` → `server/wwwroot` (команды в [DEPLOYMENT.md](../../../DEPLOYMENT.md)). `deploy/nginx.conf.example` — прод-прокси.

## Зависимости и ограничения

- Текст ≤ 10 000 символов, файл ≤ 5 МБ, блоб ≤ 8 МБ (проверка на клиенте и сервере).
- TTL до 7 дней; криптомодуль v1: Argon2id m=64 МиБ / t=3 / p=1, фраза 6–10 слов EFF large (по умолчанию 8 ≈ 103 бита, фразу создаёт клиент); параметры в заголовке конверта, парсер принимает только зарегистрированные наборы.
- Таймеры показа в payload: скрытие ≤ 1 ч, удаление ≤ 7 дней, целые ≥ 0; проверяются при шифровании и при разборе.
- Ключи и фразы существуют только на устройствах сторон.
- Инфраструктура: один процесс (Kestrel на localhost за nginx), LiteDB (managed), 1 vCPU / 512 МБ RAM достаточно.

## Критерии приёмки

- Текст, файл и текст+файл создаются, читаются и расшифровываются корректно.
- Настройки показа (скрытие/удаление) едут внутри шифроблоба; таймеры применяются у получателя после расшифровки.
- В исходящем к серверу трафике только шифротекст и идентификаторы (проверяется перехватом запросов).
- Расшифровка выполняется только с верной фразой; сервер работает с блобом как с непрозрачными байтами.
- One-time: первое чтение возвращает блоб и удаляет секрет, повторный GET — 404; параллельные GET одного one-time секрета выдают блоб ровно один раз; GET выполняется только по нажатию «Открыть»; запрос статуса возвращает флаг доступности; неверная фраза — повторная расшифровка по локальной копии блоба.
- Режим «ключ в ссылке»: чтение без ввода фразы; ключ остаётся во фрагменте браузера; после открытия страницы фрагмент срезается из URL и истории; блобы двух режимов неразличимы по форме.
- Сгенерированная фраза: состоит из слов EFF large, число слов в границах 6–10; значения вне диапазона (5, 11, дробное число слов) отклоняются.
- Просроченный секрет удаляется чисткой; блоб > 8 МБ отклоняется сервером (413); при исчерпании квоты хранилища POST — 507, освобождение (сжигание/чистка) возвращает приём.
- ID секрета неугадываем (128 бит); аккаунты/cookies отсутствуют.

## Проверки

- Клиент: `cd client && npm test` — unit-тесты криптомодуля (`client/tests/crypto.test.ts`, встроенный test runner Node): roundtrip конверта v1 (оба режима), неверная фраза/ключ, подмена заголовка/шифротекста, лимиты, настройки показа, генерация фразы (число слов, границы).
- Сервер: `cd server && dotnet test` — create→get→404, лимиты 8 МиБ и TTL, рейт-лимит 429, гонка параллельных one-time чтений (ровно одна выдача), квота 507 и освобождение после сжигания, параллельные вставки в границах квоты, `no-store` на выдаче.
- Сборка и запуск: таргет `BuildClient` собирает клиента при сборке сервера; Run (F5) в Rider или `dotnet run --project server/Momentum.csproj`; публикация — профиль linux-x64 ([архитектура](../../architecture/INDEX.md)).
- E2E на живом сервере: против собранного `./Momentum` — создание/чтение/сжигание/SPA-fallback (выполнялось tsx-скриптом с реальным конвертом v1, оба режима).
