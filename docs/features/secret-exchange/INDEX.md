# Обмен секретами

## Статус

MVP реализован (сервер + клиент + сборка). E2E пройден. Остаток: замер времени Argon2id на средних смартфонах; выкладка на VPS.

## Описание

Отправитель на странице клиента пишет текст (≤ 10 000 символов) и/или прикладывает файл (≤ 5 МБ). Клиент генерирует парольную фразу (редактируется пользователем), выводит её отправителю и шифрует всё содержимое локально (Argon2id + AES-256-GCM, версионированный конверт). На сервер уходит только шифроблоб с TTL (по умолчанию 24 ч, максимум 7 дней). Отправитель передаёт получателю ссылку и фразу любыми каналами по своему выбору. Получатель открывает ссылку, вводит фразу, клиент расшифровывает локально. По умолчанию секрет сгорает после первого чтения.

## Ожидаемый результат

Веб-страница, на которой за один экран можно: создать секрет → получить ссылку и фразу → передать их получателю → получатель прочёл → секрет уничтожен. Без регистрации.

## Поведение

- Создание: форма текста + файл; выбор режима передачи ключа: «ключ в ссылке» (по умолчанию, без фразы, ключ в URL-фрагменте) или «фраза отдельно» (фраза генерируется и редактируется); выбор TTL (24 ч по умолчанию, ≤ 7 дней); переключатель «сжечь после прочтения» (включён по умолчанию); настройки показа у получателя: «скрыть содержимое через» (выкл/15 с/30 с/60 с, по умолчанию 30 с) и «удалить со страницы через» (выкл/5 мин/10 мин/30 мин, по умолчанию 10 мин). Настройки показа зашифровываются в payload (поле `view`), серверу не видны.
- Чтение: страница `/s/<id>` сразу проверяет доступность (`GET /api/v1/secrets/{id}/status` — без передачи блоба и без сжигания one-time); недоступен — сообщение «уже прочитан или срок истёк» вместо кнопки «Открыть», полезно при повторной передаче ссылки. Далее — предупреждение об одноразовости рядом с кнопкой «Открыть»; блоб запрашивается у сервера только по нажатию (открытие ссылки само по себе не сжигает one-time секрет). В режиме «ключ в ссылке» поле фразы не показывается; если фрагмент ссылки повреждён, запрос не выполняется вовсе. Далее расшифровка на клиенте; неверная фраза/ключ — ошибка без раскрытия данных. Содержимое: сообщение с «Копировать», вложение с «Скачать». Подсказка под содержимым отражает только включённые таймеры: при скрытии — «Через N с содержимое скроется — кнопка на занавесе вернёт его», при удалении — «Через N мин оно будет удалено со страницы — необратимо»; без таймеров — «Сохраните нужное перед закрытием страницы». Если включено удаление — по истечении таймера содержимое стирается со страницы необратимо (дедлайн не сдвигается повторными показами), вместо занавеса — сообщение об удалении.
- Хранение: сервер видит только непрозрачный блоб, ID, время жизни и флаг one_time; режим конверта и настройки показа серверу не видны.
- Удаление: первое чтение (one_time) или TTL — что раньше; физическое удаление записи.

## Область

Веб-клиент (создание и чтение), серверное API `POST/GET /api/v1/secrets` и `GET /api/v1/secrets/{id}/status` (доступность без блоба), фоновая чистка просроченного, криптомодуль клиента.

## Вне области

Аккаунты и профили, чаты/история, push, несколько получателей, QR, нативные мобильные приложения, паддинг трафика, расширенный публичный API.

## Затрагиваемые части

`client/` — Expo web (криптомодуль `src/crypto.ts`, экраны Create/Read, API). `server/` — ASP.NET Core Minimal API, слои: `Api/` (`VaultEndpoints` — HTTP-обработчики; маршруты в `Program.cs`), `Domain/` (`VaultService` — правила TTL/id/размера), `Infrastructure/` (`VaultStore` — LiteDB, фоновая чистка), `Installers/` (типизированный конфиг `MomentumOptions`/`VaultOptions`/`RateLimiterLimits`, DI, конвейер), `Constants/`, точка сборки `Program.cs`, тесты. Стык клиент→сервер: `client/dist` → `server/wwwroot` (команды в [архитектуре](../../architecture/INDEX.md)). `deploy/nginx.conf.example` — прод-прокси.

## Зависимости и ограничения

- Текст ≤ 10 000 символов, файл ≤ 5 МБ, блоб ≤ 8 МБ (проверка на клиенте и сервере).
- TTL ≤ 7 дней; криптомодуль v1: Argon2id m=64 МиБ / t=3 / p=1, фраза 8 слов EFF large (≈ 103 бита); параметры в заголовке конверта, произвольные не принимаются.
- Таймеры показа в payload: скрытие ≤ 1 ч, удаление ≤ 7 дней, целые ≥ 0; проверяются и при шифровании, и при разборе.
- Ключи и фразы через сервер не проходят ни в каком виде.
- Инфраструктура: один процесс (Kestrel на localhost за nginx), LiteDB (managed, без натива), 1 vCPU / 512 МБ RAM достаточно.

## Критерии приёмки

- Текст, файл и текст+файл создаются, читаются и расшифровываются корректно.
- Настройки показа (скрытие/удаление) едут внутри шифроблоба; таймеры применяются у получателя после расшифровки, у сервера их нет.
- В исходящем к серверу трафике нет фразы, ключей и открытого текста (проверяется перехватом запросов).
- Без (или с неверной) фразой расшифровка невозможна; сервер не может проверить верность фразы.
- One-time: первое чтение возвращает блоб и удаляет секрет, повторный GET — 404; до нажатия «Открыть» на странице чтения GET не выполняется и секрет не сгорает; предварительный запрос статуса не сжигает one-time и не передаёт блоб.
- Режим «ключ в ссылке»: чтение без ввода фразы; ключ в фрагменте не доходит до сервера; блобы двух режимов неразличимы по форме.
- Просроченный секрет удаляется чисткой; лимит блоба > 8 МБ отклоняется сервером.
- ID секрета неугадываем (128 бит); аккаунты/cookies отсутствуют.

## Проверки

- Клиент: `cd client && npm test` — unit-тесты криптомодуля (`client/tests/crypto.test.ts`, встроенный test runner Node): roundtrip конверта v1 (оба режима), неверная фраза/ключ, подмена заголовка/шифротекста, лимиты, настройки показа.
- Сервер: `cd server && dotnet test` — create→get→404, лимиты 8 МиБ и TTL, рейт-лимит 429.
- Сборка и запуск: таргет `BuildClient` собирает клиента при сборке сервера; Run (F5) в Rider или `dotnet run --project server/Momentum.csproj`; публикация — профиль linux-x64 ([архитектура](../../architecture/INDEX.md)).
- E2E на живом сервере: против собранного `./Momentum` — создание/чтение/сжигание/SPA-fallback (выполнялось tsx-скриптом с реальным конвертом v1, оба режима).
