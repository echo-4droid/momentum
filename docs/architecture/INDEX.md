# Архитектура

## Статус

Стек и криптомодуль v1 зафиксированы; MVP реализован (server/ + client/), E2E пройден. Остаток: замер времени Argon2id на средних смартфонах, выкладка на VPS (deploy/nginx.conf.example).

## Назначение проекта

Обмен зашифрованными сообщениями/файлами по одноразовым ссылкам с E2EE: сервер — «глупое» хранилище шифротекста с TTL, вся криптография на клиенте.

## Стек

- Клиент: React Native → web (Expo SDK, TypeScript), WebCrypto + Argon2id (WASM, hash-wasm). Статический бандл.
- Сервер: C# / ASP.NET Core Minimal API, self-contained publish, один процесс, статика клиента из того же процесса.
- Требования к инфраструктуре: 1 vCPU / 512 МБ RAM / 5–10 ГБ диск, Linux.

## Криптомодуль v1

- Фраза: 8 слов EFF large (7776), разделитель «-», ≈ 103.4 бита; CSPRNG с reject-семплированием; ввод нормализуется (trim → NFKC → UTF-8) перед KDF.
- KDF: Argon2id m = 65536 КиБ, t = 3, p = 1, salt 16 байт, ключ 32 байта; WASM, однопоточно, без COOP/COEP; ориентир ≤ 2–3 с на средних мобильных.
- Шифр: AES-256-GCM (WebCrypto), nonce 12 байт, тег 16 байт в конце; AAD = заголовок конверта.
- Конверт: magic `MOMO` (4 б) | version (1 б) | alg_id (1 б) | m_kib (u32 LE) | t | p | salt_len | nonce_len | salt | nonce | ciphertext‖tag. Заголовок до шифротекста — 42 байта; побайтовая таблица в [idea.md](../../idea.md).
- Режимы: alg_id 0x01 — фраза + Argon2id (по умолчанию); alg_id 0x02 — «ключ в ссылке»: ключ 32 байта CSPRNG в URL-фрагменте (браузер его на сервер не отправляет), в заголовке m/t/p = 0, salt — случайный неиспользуемый. Layout одинаков, блобы неразличимы по форме; AAD покрывает alg_id — режимы взаимно не подменяемы.
- Версии: version маппится на зарегистрированный набор параметров с валидацией; новые дефолты только новой версией (+1, без переиспользования), reader поддерживает все старые, writer пишет последнюю; сервер, API и формат ссылки от версий не зависят.

## Компоненты и границы

- Веб-клиент (SPA): создание секрета, генерация и ввод парольной фразы, шифрование/расшифровка, чтение по ссылке.
- Сервер API: приём/выдача непрозрачных шифроблобов, лимит 8 МБ, TTL 1 ч–7 дней (по умолчанию 24 ч), one-time чтение с транзакционным удалением (блоб — только победителю удаления, параллельные чтения не дают двойной выдачи), квота суммарного размера блобов (2 ГиБ + резерв диска, сверх — 507; счётчик сериализован в процессе, при старте — миграция и пересчёт), проверка доступности без выдачи блоба (`/{id}/status` — для мгновенного статуса на странице чтения). Ответы GET — `Cache-Control: no-store` (шифротекст не оседает в кэше браузера). Потолок параллельных соединений Kestrel — 8 (замер: 16 загрузок по 8 МиБ давали пик 470 МиБ — впритык к профилю 512 МиБ).
- Фоновый сервис чистки: удаление просроченного.
- Хранилище: LiteDB (полностью managed — нативных библиотек в пакете нет, работает на любом glibc, который тянет .NET).

## Данные и интеграции

Единственная сущность: `id (16 байт, CSPRNG) | blob ≤ 8 МБ | expires_at | one_time | created_at`.
Внешних интеграций нет; клиент не делает внешних запросов (ассеты self-hosted).

## Развёртывание и эксплуатация

Сборка клиента вшита в сборку сервера (MSBuild-таргет `BuildClient` в `Momentum.csproj`): любая сборка сервера сама делает `npm install` (если нужно) → `expo export --platform web` → копирование `client/dist` в `wwwroot`. Отключить: `-p:EnableBuildClient=false`.

- Разработка: открыть `momentum.slnx` (в корне репо) в Rider → Run (F5) по профилю Momentum — клиент и сервер одной кнопкой, сервер на `127.0.0.1:8080`, браузер открывается автоматически. CLI: `dotnet run --project server/Momentum.csproj`.
- Публикация self-contained: `cd server && dotnet publish Momentum.csproj /p:PublishProfile=linux-x64` (или Publish в Rider с профилем linux-x64) → `server/publish/`. Важно: указывать путь к csproj — без него из `server/` dotnet подхватит солюшен `momentum.slnx` и опубликует и тестовый проект.

Пакет = один бинарник ~97 МиБ + `wwwroot/`, нативных библиотек нет: на VPS не нужны SDK, .NET-runtime и внешние БД — только nginx и TLS-сертификат. Пошаговое ручное развёртывание (systemd, nginx, TLS, файрвол, обновление): [DEPLOY.md](../../DEPLOY.md). TLS-терминация на nginx (пример: [deploy/nginx.conf.example](../deploy/nginx.conf.example)), Kestrel слушает только на localhost — портов наружу нет. Access-логи выключены, рейт-лимиты в памяти. Криптосхема и модель безопасности: [idea.md](../../idea.md).
