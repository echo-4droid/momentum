# momentum — идея и требования

Сервис одноразового обмена зашифрованными сообщениями и файлами.
Отправитель создаёт секрет локально → получает ссылку → передаёт её получателю любым каналом.
Сервер хранит только шифротекст; ключ (парольная фраза — или ключ в фрагменте ссылки в режиме F8) существует только у отправителя и получателя и никогда не проходит через сервер.

## 1. Суть и цели

- Простой E2EE-обмен: текст, файл или текст+файл одной ссылкой.
- Никаких аккаунтов, регистрации, профилей.
- Минимальная инфраструктура: один процесс, одно хранилище-файл, самый дешёвый VPS.
- Минимальный цифровой след: на сервере нет ничего, кроме шифротекста и времени жизни.

## 2. Функциональные требования

| # | Требование |
|---|---|
| F1 | Сообщение: текст ≤ 10 000 символов, файл ≤ 5 МБ, или текст+файл вместе |
| F2 | Шифрование и расшифровка — только на клиенте |
| F3 | Ключи никогда не летят через сервер: парольную фразу пользователь передаёт получателю вне сервиса, в ссылке только ID секрета |
| F4 | TTL: по умолчанию 24 часа, максимум 7 дней; по истечении — безвозвратное удаление |
| F5 | По умолчанию «сжечь после прочтения»: удаление сразу после первого чтения (или по TTL, что раньше); опция — повторные чтения до конца TTL |
| F6 | Защита высокая по умолчанию и повышаемая: параметры Argon2id и алгоритмы версионируются в конверте |
| F7 | Доступ только по ссылке; ID секрета случайный, 128 бит → перечисление невозможно |
| F8 | Режим передачи ключа на выбор: «фраза отдельно» (по умолчанию) или «ключ в ссылке» — без фразы, ключ в URL-фрагменте, который браузер не отправляет |

## 3. Модель безопасности

Защищено:
- компрометация или изъятие сервера → утекает только шифротекст;
- администратор сервера → содержимого не видит; сервер даже не может проверить верность фразы — расшифровка на клиенте;
- пассивный наблюдатель сети → HTTPS; в трафике к серверу нет ни фразы, ни ключей, ни открытого текста;
- логирование ссылки мессенджером → ссылка не содержит ключа, без фразы бесполезна.

Не защищено (принимаем осознанно):
- компрометация устройства отправителя/получателя;
- активная подмена клиентского JS скомпрометированным сервером: владеющий сервером может подменить статику и получить ключ/фразу и содержимое при следующем открытии (пассивная компрометация при этом раскрывает только шифротекст); митигации — self-host клиента или подписанные сборки, вне рамок v1;
- передача фразы тем же каналом, что и ссылки — защита сводится к одному фактору; для этого случая есть осознанный режим «ключ в ссылке» (F8): один фактор без лишнего шага;
- режим «ключ в ссылке» (F8): логирование полного URL (с фрагментом) раскрывает содержимое; митигируется одноразовостью (F5) и выбором режима фразы;
- оффлайн-перебор фразы по перехваченному шифротексту — митигируется высокой энтропией сгенерированной фразы;
- доступность: DoS или изъятие сервера останавливают сервис, но не раскрывают данные;
- размер трафика: сервер видит длину шифротекста; паддинг — опционально, не в v1.

## 4. Криптосхема

Версионированный конверт: `[magic][version][params][salt][nonce][ciphertext]`.
Параметры (алгоритм, настройки Argon2id) лежат в заголовке конверта — дефолты можно поднимать сменой версии, старые ссылки читаются по своей.

v1 (зафиксировано):
- Два режима передачи ключа, одинаковый 42-байтовый layout — блобы режимов неразличимы по форме (наблюдатель и сервер не видят, какой выбран):
  - «фраза отдельно» (по умолчанию), alg_id 0x01: ключ = Argon2id(фраза);
  - «ключ в ссылке» (F8), alg_id 0x02: ключ 32 байта CSPRNG в URL-фрагменте `https://host/s/<id>#<base64url>`; в заголовке m/t/p = 0, salt — случайные неиспользуемые байты.
- Парольная фраза (режим 0x01): 8 слов из EFF large wordlist (7776 слов), разделитель «-», энтропия ≈ 103.4 бита; выбор слов CSPRNG с reject-семплированием; редактируется пользователем. Любой ввод нормализуется: trim → NFKC → UTF-8. Фраза в конверт не входит.
- KDF: Argon2id, m = 65536 КиБ (64 МиБ), t = 3, p = 1 (второй профиль RFC 9106); salt 16 байт CSPRNG; ключ 32 байта. Ориентир: ≤ 0.5 с на десктопе, ≤ 2–3 с на средних смартфонах.
- Шифр AES-256-GCM (нативный WebCrypto), nonce 12 байт CSPRNG, тег 16 байт в конце шифротекста; AAD = весь заголовок конверта (режимы взаимно не подменяемы).
- Внутренний payload: JSON `{ text?, file?: { name, mime, data(base64) } }`.
- Ссылка содержит только ID (режим 0x01) или ID + фрагмент-ключ (режим 0x02).

Раскладка конверта v1 (целые little-endian, заголовок до шифротекста — 42 байта):

| Смещение | Поле | Размер | Значение |
|---|---|---|---|
| 0..3 | magic | 4 б | ASCII `MOMO` |
| 4 | version | 1 б | 0x01 |
| 5 | alg_id | 1 б | 0x01 = Argon2id(фраза), 0x02 = ключ из ссылки |
| 6..9 | m_kib | uint32 | 65536 |
| 10 | t | 1 б | 3 |
| 11 | p | 1 б | 1 |
| 12 | salt_len | 1 б | 16 |
| 13 | nonce_len | 1 б | 12 |
| 14..29 | salt | 16 б | CSPRNG |
| 30..41 | nonce | 12 б | CSPRNG |
| 42.. | ciphertext | остальное | payload ‖ GCM-тег (16 б) |

Передача ключа: фраза уходит получателю любым каналом вне сервиса (голос, другой мессенджер, лично). Через momentum-сервер фраза не проходит никогда.

Повышение надёжности (версии конверта):
- version → зарегистрированный набор {kdf, alg, m, t, p, длины}; парсер сверяет значения с набором, произвольные параметры не принимаются;
- новая версия (+1, номер не переиспользуется) — единственный способ поднять дефолты; условие подъёма: новый набор укладывается в ~2–3 с на средних мобильных;
- writer пишет только последнюю версию, reader поддерживает все предыдущие; старые ссылки не ломаются, серверу версия безразлична (blob непозрачен);
- (позже) XChaCha20-Poly1305 как альтернативный шифр.

## 5. Лимиты и валидация

- Текст ≤ 10 000 символов, файл ≤ 5 МБ; суммарный шифроблоб ≤ 8 МБ (запас на base64-оверхед ~33%).
- Лимиты проверяются дважды: на клиенте (UX) и на сервере (граница доверия — сервер режет всё > 8 МБ).
- `ponytail:` v1 — base64 внутри JSON; сырой бинарный конверт нужен, только если лимит файла вырастет.

## 6. Хранение и TTL

- Хранилище: LiteDB (полностью managed, без нативных зависимостей — работает на любом glibc).
- Запись: `id (16 байт) | blob | expires_at | one_time | created_at`. Ничего больше.
- Фоновая служба чистит просроченное раз в минуту.
- Квота хранилища: суммарный размер блобов ≤ `Vault:MaxTotalBytes` (2 ГиБ по умолчанию) плюс резерв свободного места диска (`DiskReserveBytes`, 512 МиБ); при превышении POST — 507. Счётчик занятых байтов ведётся транзакционно, чистка пересчитывает его раз в минуту.
- One-time секрет: чтение с удалением в одной транзакции; блоб получает только победитель удаления (DeleteMany > 0) — параллельные чтения не выдают секрет дважды.

## 7. API (набросок)

- `POST /api/v1/secrets` — тело: `ttl, one_time, blob` → ответ: `id`
- `GET /api/v1/secrets/{id}` → `blob` (для one_time — транзакционно «прочитал-и-удалил»)
- Сервер трактует blob как непрозрачные байты: не парсит, не валидирует содержимое.

## 8. Инфраструктура

- Один процесс: ASP.NET Core self-contained publish; статика веб-клиента из того же процесса (wwwroot). Без внешней БД, очередей, кэшей.
- TLS: nginx перед Kestrel; Kestrel слушает только на localhost — портов наружу нет.
- Габариты: 1 vCPU / 512 МБ RAM / 5–10 ГБ диск → минимальный VPS справится.
- Docker-образ — опционально, один Dockerfile.

## 9. Цифровой след

- Нет аккаунтов, cookies, email; клиент полностью stateless.
- Access-логи выключены; в логах только ошибки без идентификаторов запросов.
- Рейт-лимиты — в памяти процесса, не персистируются.
- Клиент: все ассеты self-hosted, ноль внешних запросов (no CDN, no analytics, no внешние шрифты).
- HSTS; опционально — зеркало как Tor onion.
- Удаление по TTL/чтению — немедленное логическое удаление записи; страницы файла БД переиспользуются и не затираются на уровне носителя. Гарантию даёт шифрование, а не стирание: скопированный ранее шифротекст остаётся расшифровываемым только при наличии ключа/фразы.

## 10. Стек (зафиксировано)

- Клиент: React Native → web (Expo SDK, TypeScript), WebCrypto + Argon2id (WASM); сборка — статический бандл.
- Сервер: C# / ASP.NET Core Minimal API + фоновый сервис чистки TTL; self-contained publish, один процесс.

## 11. Вне рамок v1 (осознанно)

Аккаунты, чаты и история, push, несколько получателей, QR-коды, нативные мобильные приложения, паддинг трафика, разделение секрета (Shamir), расширенный публичный API.

## 12. Открытые вопросы

Открытых требований нет. Остаток на этап приёмки: замер фактического времени Argon2id (m = 64 МиБ, t = 3) на среднем смартфоне; если бюджет 2–3 с не выдерживается — пересмотр требования, а не ослабление m без согласования.
